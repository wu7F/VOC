# VOC洞察平台

> Voice of Customer · 把「reddit分析」技能升级为可交互的 Web 版 VOC 洞察工具
> 支持 **AMAZON / WAYFAIR / REDDIT** 三平台，内置离线分析引擎，**无需任何 API Key 即可出结果**。

---

## 一、快速开始

### 方式 A：本机双击（最简单）

先设置口令（**公网/局域网访问必做**，见第二节），然后：

```bat
set VOC_PASSWORD=你的管理员口令
set VOC_GUEST_PASSWORD=给客户看的只读口令
双击 start.bat
```

### 方式 B：打包成独立 exe（换电脑也能跑，目标机无需 Python）

```bat
pip install pyinstaller
python build_exe.py
```

产物 `dist\VOC洞察平台\VOC洞察平台.exe`（约 130MB）。把整个目录拷到目标机器，
设置 `VOC_PASSWORD` 后双击即可。数据默认落在 exe 同级的 `VOCData/`。

### 方式 C：命令行

```bash
python web/serve.py --host 127.0.0.1 --port 8080
python web/serve.py --host 0.0.0.0 --port 8080 --data-dir D:\VOCData   # 对外提供服务
```

| 参数 | 说明 |
|---|---|
| `--host` | 默认 `127.0.0.1`（仅本机）；给局域网/公网用 `0.0.0.0` |
| `--port` | 默认 8848；被占用时自动向后顺延 |
| `--data-dir` | 数据目录，见下 |
| `--no-browser` | 不自动开浏览器 |

### 数据目录

| 优先级 | 位置 |
|---|---|
| 1 | 环境变量 `VOC_DATA_DIR` / `--data-dir` |
| 2 | 打包 exe → `<exe 同级>/VOCData` |
| 3 | 源码运行 → 项目根目录（兼容旧部署） |

```
VOCData/                 ← 数据（整目录拷走 = 完成迁移 / 备份）
├── runs/                 分析产出（_index.json + 每条记录的目录）
├── data/                 演示数据
├── llm_config.json       LLM 配置（含密钥，勿外传）
└── .session_secret       会话签名密钥（自动生成）
```

## 二、账号登录

平台放到公网后，**任何人拿到网址都能删光你的报告**。所以账号体系是暴露到公网的**前置条件**。

### 账号即邮箱，不分角色

| | 说明 |
|---|---|
| 账号 | **邮箱地址**，唯一身份标识 |
| 密码 | 由你自己设定，**PBKDF2-HMAC-SHA256 + 随机盐**存储，文件里没有明文 |
| 权限 | **所有账号完全相同**：新建 / 重跑 / 删除 / 清理残留 / 导出 / 查看全部 |
| 注册 | **无自助注册**。账号由持有本机磁盘访问权的人创建 |

> **为什么账号管理不开放网页接口？**
> 因为不分角色，任何登录的人权限都一样 —— 如果网页上能自助注册或删账号，
> 等于任何拿到网址的人都能给自己加账号、或把别人的账号删掉。
> 所以账号增删只在**这台电脑上**用命令行完成。

### 管理账号

```
账号管理.bat                    列出全部账号
账号管理.bat add                交互式添加（会询问密码，输入不回显）
账号管理.bat passwd 邮箱         修改密码
账号管理.bat remove 邮箱         删除账号
```

也可直接用 Python：

```bash
python manage_accounts.py list
python manage_accounts.py add someone@example.com        # 交互式询问密码
python manage_accounts.py add someone@example.com MyPwd123
python manage_accounts.py passwd someone@example.com NewPwd456
python manage_accounts.py remove someone@example.com
```

账号文件：`VOCData/accounts.json`（与 `runs/` 一起备份迁移）。

### 登录体验

登录页只填**邮箱 + 密码**。进入后右上角显示当前账号，浏览器标题也会带上邮箱。

**登录细节：**

- **失败提示**：区分三类情况 —— 邮箱/密码错误（红色，附带"还可尝试 N 次"）、
  尝试过频被临时锁定（橙色，带秒级倒计时，期间自动禁用表单）、普通提示（蓝色）。
  失败时输入框抖动、密码清空、焦点回到密码框，方便立刻重试。
- **记住密码**：勾选后凭据保存在**本机浏览器** `localStorage`（密码经 base64 简单混淆，
  非加密，不上送服务器），下次进入自动回填。在公共电脑上请勿勾选。
- **显示密码**：密码框右侧的眼睛按钮可临时把密码显示为明文。

已实现的防护：

- 登录失败 8 次 → 锁定该 IP 5 分钟（提示会显示剩余次数与解锁倒计时）
- 会话用 HMAC 签名 Cookie（`httponly`），密钥随机生成后落盘 `VOCData/.session_secret`
- 上传单文件上限 200MB（`VOC_MAX_UPLOAD_MB` 可调）
- 异常信息里的绝对路径被剥离为 `<路径>`，不泄漏磁盘结构
- 邮箱不存在时也会走一遍哈希运算，避免"邮箱是否注册"成为可探测的侧信道

### 一个账号都没有时

本机 `127.0.0.1` 照常可用一切，**远程一律拒绝写操作**。
这样"还没配账号"不会导致公网裸奔，同时不破坏"本机双击即用"的体验。

> 升级说明：早期版本用的是 `VOC_PASSWORD` / `VOC_GUEST_PASSWORD` 两个环境变量口令
> （管理员 / 只读访客）。若首次启动时还没有账号文件，会自动从这两个环境变量引导创建账号，
> 之后一律以 `accounts.json` 为准。

## 三、三个板块

| 板块 | 数据类型 | 支持的文件 | 特点 |
|---|---|---|---|
| **AMAZON** | 商品评论导出 | `.xlsx` / `.csv` / `.tsv` / `.jsonl` | 星级作为情感先验；评论者默认视为已购 |
| **WAYFAIR** | 商品评论导出 | 同上 | 若含 `Annotations` 列，直接采用平台打标结果提升功能维度准确度 |
| **REDDIT** | 帖子 + 评论 | 同上，可**多文件**上传 | 自动把「每帖前 N 条评论」并入讨论单元；证据区分 💬 评论 / 📄 正文 |

### Reddit 支持三种上传形态

| 形态 | 说明 |
|---|---|
| **单文件混合导出** | 一张表里 `type=post` / `type=comment` 混排（Reddit 导出工具的常见形态）。平台按 `type` 拆分，帖子行取 `content` 作为标题。 |
| **帖子 + 评论两个文件** | 分别上传帖子表与评论表，平台按列特征自动区分两者，用 `post_reddit_id` 关联。 |
| **只有帖子** | 无评论时也能分析，只是证据全部来自正文。 |

> 若只上传评论文件（没有配套帖子），平台无法组成讨论单元，会明确提示需要一并上传帖子文件。

**列名自动识别**（无需改表头）：平台内置别名表，可识别

- 商品/评论：`ASIN` `SKU` `Supplier part number` `Product name` `Rating` `Star Rating` `Review text` `Review Body` `Review date` `Store name` `Annotations` …
- Reddit：`reddit_id` `title` `summary_text` `subreddit` `body` `comment_id` `post_reddit_id` `type` …

若列名不在别名表内，平台会在上传区提示需要映射的字段。

## 四、分析流程

上传 → 平台适配 → 时间清洗 → 语义标注 → 聚合 → 看板 + 报告

七个分析维度：

```
购买状态  ·  人群画像  ·  使用场景  ·  购买前关注点
购买后体验  ·  功能体验  ·  未满足需求
```

结果页六个页签：**概览 / 六维分析 / 功能体验 / 人群与交叉 / 数据原声 / 报告**

### 「人群 × 功能」热力图有两处，用途不同

两处用的是**同一份 `persona_feature_matrix`**，但取向与配色相反，回答的是两个不同问题：

| 位置 | 纵轴 / 横轴 | 色块含义 | 单元格数字 | 回答的问题 |
|---|---|---|---|---|
| **功能体验** 页签 | 功能 / 人群 | **提及量**（蓝色越深讨论越多） | 满意度%，绿 ≥80% / 黄 50–80% / 红 <50% | 这个功能**被讨论得多不多**？谁在讨论？他们满意吗？ |
| **人群与交叉** 页签 | 人群 / 功能 | **满意度**（绿色越深越满意） | 满意度% | 这类人群**对哪些功能不满**？ |

配色是刻意错开的：功能页用蓝＝热度、数字用红绿＝好坏；人群页整格用绿红＝好坏。
这样在任一处都能一眼看出「高热度 + 低满意」的格子——那是最该优先处理的问题。

> 两处都只统计**有一手使用经验**的单元（选购期的预期不计入功能满意度），
> 点击单元格都会聚焦到「数据原声」页对应的证据。

## 五、内置离线引擎（默认）

`server/offline_engine.py` + `server/taxonomy.py` 构成一套**词典 + 规则**驱动的 VOC 标注引擎：

1. 把讨论单元切成句子；
2. 用 7 维度、约 70 个标签的正则词典在**句子窗口内**匹配（避免跨句误判）；
3. 对命中句做情感判定（含否定翻转；电商语料以星级为先验）；
4. 把命中的**原句逐字**作为证据 —— 因此报告里的每条引用都能在原文中找到，不存在编造。

引擎为确定性实现（无随机性），同一份输入重复运行结果完全一致，处理速度约 100 单元/秒。

### 两个关键口径

| 概念 | 含义 | 用途 |
|---|---|---|
| **购买状态** | 论坛按**发帖人立场**判定（选购者 / 已购用户）；**电商一律判为已购买** | Reddit 的「已购 / 未购人群画像对比」；电商只出「购买人群画像」 |
| **有一手使用经验** | 单元（含评论）出现已购 / 在用自述；**电商默认全部为真** | 「人群 × 功能满意度交叉」的分母 |

之所以分开：论坛里发帖人常是选购者、回帖老用户才是真实使用者。若把两者混为一谈，
「已购人群」会被老用户的评论淹没，画像对比失去意义；而功能满意度又必须来自真实使用者。
因此画像对应用发帖人立场，功能满意度用使用经验。

> **电商为什么没有「未购买人群」？** Amazon / Wayfair 的评论只能来自真实买家，
> 评论即已购。所以引擎对电商**强制判为 `purchased`**（`offline_engine.py` / `llm_engine.py`
> 里以 `default_purchase == "purchased"` 判定），不会因为文案里出现「还没买 / 打算买」
> 这类句子就凭空造出一批并不存在的未购买人群。
> 对**旧数据**做了兜底：若历史记录里仍有被判为未购的单元，界面会把它们的画像**并回购买人群**，
> 并在副标题注明「含 N 次早期判定的『未购』提及，已并入购买人群」，避免静默丢样本。

> 副作用提醒：论坛的「购买状态」与「使用经验」均为**基于文本的推断**，不是事实，
> 建议对关键结论人工抽样复核。
> 判定阈值集中在 `taxonomy.PURCHASED_PATTERNS` / `NOT_PURCHASED_PATTERNS` 与
> `offline_engine.detect_op_stance()`，可直接收紧或放宽。

## 六、分析引擎：内置引擎 / LLM

平台有两种引擎，**产出完全相同的数据契约**，前端与报告层不区分来源。

| 引擎 | 说明 |
|---|---|
| **内置引擎**（默认） | 本地词典 + 规则，无需联网、无调用成本，约 100 单元/秒。证据天然逐字可溯源。 |
| **LLM** | 为**当前品类**现生成专属标签体系，再做语义标注。召回与语义精度更高，需要联网与额度。 |

### 配置 LLM

方式一：编辑项目根目录的 `llm_config.json`

```json
{
  "base_url": "https://api.deepseek.com/v1",
  "api_key": "sk-...",
  "model": "deepseek-chat"
}
```

方式二：环境变量（**优先级高于配置文件**）

```bash
export LLM_CONNECTOR_BASE_URL=https://api.deepseek.com/v1
export LLM_CONNECTOR_API_KEY=sk-...
export LLM_CONNECTOR_MODEL=deepseek-chat
```

改完需**重启服务**。可用 `python -c "from server import llm; print(llm.preflight())"` 自检，
或直接点界面右上角的引擎状态胶囊。

> ⚠️ `llm_config.json` 里存的是明文密钥。该文件只在本机读取，服务默认只监听 `127.0.0.1`，
> 但请勿把这个文件随项目一起分享出去。多人使用时建议改用环境变量。

### 三种引擎模式

| 模式 | 行为 |
|---|---|
| **自动**（默认） | 配了 LLM 就用 LLM；若后端不可用（欠费 / 断网 / 鉴权失败），**自动回退内置引擎**并在结果页给出橙色告警，说明回退原因。 |
| **LLM** | 强制使用 LLM。失败时**直接报错，不静默降级** —— 避免你在不知情的情况下拿到内置引擎的结果。 |
| **内置引擎** | 强制本地引擎，不发起任何外部请求。 |

### LLM 路径的可信性保障

模型给出的每条引用都会**回到原文逐字回查**：命中则存**原文切片**，命中不到则丢弃该标签并计数。
因此即使模型产生幻觉引用，也不会进入结果。
结果页会显示如「丢弃了 N 条无法在原文定位的引用」，这个数字应当被当作**模型质量的体检指标**：
长期偏高说明该模型在引用上不稳定，建议在报告里对结论再做人工抽样复核。

## 七、报告记录（按平台分板块）

每次分析都会**自动保存为一条报告记录**，重启服务、关掉浏览器都不会丢——
记录索引写在 `runs/_index.json`，产出（`result.json` / `report.md` / `tags.json`）在 `runs/<记录 id>/`。

**每条记录都完整涵盖六个板块**：概览 · 六维分析 · 功能体验 · 人群与交叉 · 数据原声 · 报告。
重新打开一条记录时六个板块全部可复现，不依赖当时的上传文件（数据早已落盘在 `runs/<id>/`）。

### 6.1 每个平台一个报告记录板块

**AMAZON / WAYFAIR / REDDIT 三个板块各自独立收集自己的 VOC 报告**，互不混杂。
点击侧边栏顶部 **「XX 报告记录 · 查看 ›」**、新建分析页的 **「本平台报告记录」** 按钮，
或访问 `#records`，都会进入当前平台的报告记录板块。

板块顶部是**平台子板块切换条**（`AMAZON 0` / `WAYFAIR 1` / `REDDIT 5` / `全部平台 6`）：

- 切到顶部 `AMAZON / WAYFAIR / REDDIT` 导航时，报告记录自动跟随到该平台；
- 点子板块上的「全部平台」可跨平台汇总，此时才出现平台下拉筛选；
- 某平台还没有报告时显示专属空状态（"XX 板块下还没有报告 / 上传该平台数据即可生成报告"）；
- 侧边栏列表与板块范围保持一致：在 `REDDIT` 板块下，侧边栏也只列 Reddit 的报告。

### 6.2 每条报告的操作

| 操作 | 说明 |
|---|---|
| **查看报告** | 打开该报告并**直接跳到「报告」页签**（点卡片本体等同此操作）。其余五个板块可再点页签切换 |
| **导出 PDF** | 无需进入看板，直接把六个板块（含全部图表）导出为 PDF |
| **删除** | 单条删除，删除前弹出二次确认，并同步清除该记录在 `runs/` 下的产出目录 |
| **批量删除** | 工具条「批量选择」→ 勾选（支持全选）→「删除所选 N 条」 |

其它能力：

| 能力 | 说明 |
|---|---|
| **搜索** | 按品类 / 名称 / 品牌实时过滤 |
| **时间排序** | 默认**最新在前**，可切换最早在前；偏好记在浏览器本地，下次打开保持 |
| **六板块标记** | 卡片上的 `概览 六维 功能 人群 原声 报告` 标签，标明这条报告覆盖了哪些板块 |
| **引擎徽标** | `LLM 引擎` / `内置引擎` 徽标，便于对比同一样本在不同引擎下的差异 |

删除**不可撤销**，为避免误删一律二次确认。

> 想让列表更干净？直接删掉不需要的报告即可，不会影响其它记录。
> 若想整体重置，停掉服务后清空 `runs/` 目录（`_index.json` 与各记录目录）再启动。

### 6.3 删除是「真删除」，不留残留

删除一条报告，会连带清掉三样东西，而不只是把它从列表里藏起来：

| 清掉的东西 | 位置 |
|---|---|
| 记录条目 | `runs/_index.json` |
| 全部产出 | `runs/<记录 id>/`（`result.json` / `report.md` / `tags.json` / `units.jsonl` / `error.log`） |
| **上传的原始数据文件** | `runs/_uploads/`（每条记录保存上传时的**精确路径**，删除时按路径删，不会误伤同名文件的其他记录） |

因此磁盘占用会真正回落，不会出现「报告没了但几十 MB 原件还躺在盘上」。

早期版本（没有记录精确路径的记录）按文件名后缀匹配删除，并且会跳过仍被其它记录引用的同名文件，
避免误删——代价是这类记录的原件可能需要用下面的「清理残留」回收。

### 6.4 清理残留

历史失败、早期版本删除不彻底，会在 `runs/` 下留下**索引里查不到**的孤立目录，
在 `_uploads/` 下留下无主原件。记录板块工具条会显示 **「清理残留 N」** 按钮（干净时不显示），
点它会先列出将要删除的数量与占用体积，确认后一次清干净。

也可以直接调用接口：

```bash
curl http://127.0.0.1:8080/api/maintenance/status   # 只看统计
curl -X POST http://127.0.0.1:8080/api/maintenance/cleanup   # 执行清理
```

> 清理**只动索引里查不到的东西**：正在排队或运行的分析，其目录在索引中，不会被误删。

## 八、导出 PDF（六个板块）

结果页右上角提供两个导出按钮：

| 按钮 | 导出范围 | 说明 |
|---|---|---|
| **导出 PDF** | 全部六个板块 | 概览 → 六维分析 → 功能体验 → 人群与交叉 → 数据原声 → 报告，每个板块另起一页 |
| **导出本页 PDF** | 当前板块 | 只想留某一页时用，文件更小 |
| **查看 Markdown** | 报告正文 | 报告板块的原始 Markdown |

### 它是怎么生成的

1. 前端把六个板块**逐个真实渲染**（图表按当前数据重新绘制），然后把每个 ECharts 画布用
   `getDataURL()` 转成 PNG 内嵌，再把整份样式表内联 —— 得到一份**自包含的静态 HTML**。
2. 该 HTML 提交到 `POST /api/export/pdf`，服务端调用本机 **Chrome / Edge（headless）**
   的 `--print-to-pdf` 渲染成 PDF，作为附件直接下载。
3. 文件名形如 `Nursery_Recliner_Reddit_六板块_20261013_1520.pdf`。

因为没有外部资源依赖，服务端不需要等待任何 JS 执行或网络请求，导出稳定且与屏幕所见一致。

> **没装 Chrome/Edge 怎么办？** 页面启动时会探测（`GET /api/export/available`）。
> 若探测不到，按钮会提示改用浏览器打印：点击后在打印对话框里选「另存为 PDF」即可，内容完全相同。

也可以指定浏览器路径：

```bash
set VOC_CHROME_PATH=D:\path\to\chrome.exe
python 启动平台.py
```

## 九、指标口径

- **满意度** = 正面 /（正面 + 负面），**中性不计入分母**，使不同功能之间可比。
- **占比** = 命中单元 / 该维度命中总数（维度内分布）；**提及率** = 命中单元 / 分析单元总数。
- 标签为**多标签统计**，同一单元可命中多个标签，合计可超过 100%。
- **时间窗口**：有日期时默认只保留近两年数据（与技能原有一致）。

## 十二、常见问题

**Q：品牌维度是空的？**
单商品评论集通常不含品牌词。可在新建分析时填写品牌清单；用 `|` 合并同一品牌的多种拼写，
例如 `La-Z-Boy|Lazy Boy|La Z Boy, Monte|Monte Design`。

**Q：分析失败，提示「未能从文件中解析出任何有效讨论单元」？**
这不是笼统报错 —— 展开的红色诊断块会逐项列出：读了哪个文件、多少行、识别到哪些列、
判定成了帖子还是评论、以及缺什么。常见两种：

- *「判定为纯评论文件，但没有配套的帖子文件」* → 需要一并上传帖子表，或改用含 `type` 列的混合导出。
- *「未能找到评论正文列」* → 表里没有承载文本的列，需映射到 `Review text` / `content` / `body` 之类。

**Q：上传的 xlsx 很大（几万行），会被截断吗？**
不会。平台按行流式读取整张表，上限 20 万行；若真的超过，来源说明里会**显式标注已截断**，
不会静默丢数据。

**Q：Reddit 上传一个文件还是两个？**
都支持，也支持只有一个帖子文件。详见上文「Reddit 支持三种上传形态」。

**Q：分析很慢？**
离线引擎约 100 单元/秒。Reddit 带 1800+ 条评论的语料约 15–20 秒。若明显更慢，检查是否上传了
超大文件（>50MB）或把非本平台的文件放进了对应板块。

**Q：报告能导出吗？**
结果页「导出报告」按钮下载 Markdown；「报告」页签支持复制 Markdown 与打印成 PDF。
